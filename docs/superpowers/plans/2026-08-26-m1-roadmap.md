# M1 Roadmap: Sub-Plan Decomposition

**Spec:** `docs/superpowers/specs/2026-08-26-serpent-python-soroban-sdk-design.md` (as amended 2026-08-26)
**Findings:** `docs/superpowers/specs/2026-08-26-phase0-findings.md`
**Status:** decomposition for approval; each sub-plan is authored (full bite-sized
detail, adversarially reviewed) only when its predecessor is nearly done, so each
absorbs everything learned before it.

M1's goal (spec §11): the core SDK — types, storage, auth, events, errors, UDTs,
compiler, runtime library, testing tiers, CLI, examples, docs, CI — ending in a
deliberate, user-approved testnet deployment. Honest sizing: 3–6 months. The
decomposition below cuts that into seven sub-plans, each leaving `main` green and
independently useful. Order is dependency-driven; A→D are sequential, E onward
partially parallelizable.

| # | Sub-plan | Produces (works standalone) | Key consumers |
|---|----------|------------------------------|---------------|
| A | **Value layer** | `serpent.val` (THE codec: tags, packing, symbol/error encodings, masks) + chain-type classes (`U32`…`I256`, `Symbol`, `Bytes(N)`, `String`, `Vec`, `Map`, `Address`, `Timepoint`, `Duration`) with checked-arithmetic Python semantics, `@contracttype`/`@contracterror`/`@contractevent` decorators (self-standing, dataclass_transform, exception classes) — fully usable + Hypothesis-tested without any compiler | everything |
| B | **Host interface layer** | pinned `env.json` + bindings codegen (all 199 fns, protocol gates, raw-scalar types), computed-protocol-floor logic, `sections` module v2 (spec/env-meta/meta via stellar_sdk XDR incl. UDT + event entries, name-length validation, docstrings) with golden tests | C, D, F |
| C | **Compiler frontend** | name resolution + import handling, typed IR, type checker, diagnostics engine (source-located, `must_reject/` executable subset spec seeded from Phase 0 + the ~25 constructs users will try), `Env`/storage/auth/events API *surface* recognition | D |
| D | **Emitter + runtime library** | production emitter (operand-stack-validated, memory/data layout, scratch discipline, ABI prologues, overflow→`fail_with_error`) + pre-assembled runtime parts (i128 add/sub/mul/cmp guest code, div via host i256) + `serpent build` producing deployable WASM for the full M1 language | E, F, G |
| E | **Env runtime semantics + examples** | the authored `serpent` package's `Env` (storage tiers/TTL, `require_auth(_for_args)`, events, ledger) wired end-to-end; example contracts (counter, events, errors, structs, allowance-token-no-xcontract) compiled and passing | F, G |
| F | **Testing tiers** | tier-2a productized (pytest fixtures, feature-set assertion test, footprint recording); tier-2b `serpent-host` PyO3 package (error discrimination, panic containment incl. Address/register, wheel/protocol strategy per findings §2); differential runner (2a vs 2b vs testnet = release gate) | G |
| G | **CLI plugin + ship** | `stellar-serpent` console script (`build`/`inspect`/`doctor`), docs site (mkdocs; subset spec generated from `must_reject/`), CI (lint/typecheck/test/build/validate), README; ends with the M1 gate: user-approved testnet deploy of an example | — |

**Standing constraints for every sub-plan** (from spec + findings): single Val
codec; validate-inside-compiler; error codes never lost to `unreachable`;
`self`-first methods; exception-class errors; pre-validate at every
nominally-fallible soroban-sdk boundary; `relaxed_simd`-before-`simd`; balance
checks at `ret()`; pinned toolchain versions with drift-detection tests; every
sub-plan gets an adversarial review before execution and runs under
subagent-driven development with task-scoped reviews.

**Spike disposition:** `spikes/` stays as read-only reference evidence until
sub-plan D supersedes the emitter and F supersedes the harnesses, then a cleanup
task in G decides retain-vs-remove with the user.
