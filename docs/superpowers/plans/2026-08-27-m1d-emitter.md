# M1-D: WASM Emitter + Guest Runtime Library Implementation Plan (v2, post-adversarial-review)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lower `CompiledModule` (the M1-C frontend's output) to deployable
wasm32 bytes for the Soroban host — operand-stack-validated, with the guest
runtime library, ABI prologues, checked arithmetic, the three custom sections,
and validation inside the compiler — proven by a D-local wasmtime mini-host
running the semantics table and the Phase-0-anchored end-to-end contracts.

**Architecture:** A new `src/serpent/emitter/` subpackage (ruling E6), one small
module per concern mirroring the frontend's layout (dossier §C.1). Two-pass:
every function body is lowered and stack-checked before a single module byte is
laid out. Runtime parts are emitted from the SAME Python encoder as user code
(ruling E2 — no WAT toolchain). Execution proof at merge comes from a dev-only
wasmtime mini-host ported by copy from the spike (ruling E1), which sub-plan F
productizes; it is NOT an oracle.

**Tech Stack:** stdlib-only emitter (zero-dep walk unchanged); `serpent.spec`
(hence `stellar_sdk`) for custom sections only; `wasmtime==48.0.0` (already a
dev dep) for the test harness; `wasm-tools` optional-if-present (ruling E5).

**Spec:** `docs/superpowers/specs/2026-08-26-serpent-python-soroban-sdk-design.md`
(§4–§8, §10, §13). **Dossier (citation target for all S/R/D/A/B/C/P/E IDs):**
`docs/superpowers/specs/2026-08-27-m1d-inputs-dossier.md`. **Rulings:**
`docs/superpowers/decisions.md` 2026-08-27 "M1-D emitter rulings" (all 16

## Global Constraints

- Layout: `src/serpent/emitter/` — `__init__.py` (public: `build_wasm`,
  `build_file`, `BuildResult`, `EmitError`), `encode.py`, `opcodes.py`,
  `layout.py`, `frame.py`, `arith.py`, `lower.py`, `module.py`, `sections.py`,
  `validate.py`, `printer.py`. NOT added to `serpent.__all__` (E6);
  `tests/unit/test_public_api.py` must keep passing unchanged.
- `serpent/emitter/` sits with `serpent/compiler/` in the zero-dep walk: it
  reaches `stellar_sdk` ONLY transitively through `serpent.spec`
  (`emitter/sections.py` is the single module allowed to import
  `serpent.spec`); never import `stellar_sdk` directly. Do NOT edit
  `test_core_zero_dep.py` (review m1: the existing walk already handles
  `serpent`-rooted imports; if it fails, return BLOCKED rather than edit).
- **Value model (P11/§B.3, amended per review M1):** an expression lowering
  leaves NET exactly one `i64` when its `ty` is not `Void`, and NET zero when
  it is (a void `InternalCall` under `Eval`); transient `i32`s are consumed
  within the lowering. `frame.Fn.expr_scope(ty)` asserts the typed delta.
- **Host-import index space (review B1):** import indices are minted in
  FIRST-USE order during pass-1 lowering and that order IS the import
  section's order — never re-sorted. `call` immediates are baked during
  lowering, so any reorder after pass 1 is a wrong-target bug that validates
  (all host fns share the all-i64 shape, B3). Deterministic because lowering
  order is source order; the E7 subprocess test is the tripwire. A pass-2
  assertion recomputes name→index from the section and compares with the
  registry.
- **Divergence guards are law:** unbox to the declared width before EVERY
  scalar compare — never compare Val words (F.1.1); signedness of relops from
  `Ty` alone, never representation (F.1.11); range-check BEFORE every repack —
  the spike's wrapping `pack_u32` is the named anti-pattern (F.1.3);
  `RawScalar` → bare `i64.const`, never a packed Val (F.1.4/C13); never re-sort
  `MakeStruct.fields` or `MakeMap.pairs` (F.1.5/C9); every container mutation
  rebinds the returned handle via `SetLocal` (F.1.9); NO constant folding
  (F.1.16/C10); `Symbol` compares always via `obj_cmp` (F.1.8); the
  `unreachable` rule as ONE testable statement (E4/P14, review M3): every
  `unreachable` opcode in a module is immediately preceded by
  `call fail_with_error` with the `CODE_UNREACHABLE_GUARD` ErrorVal + `drop`
  (the diverging-tail guard); no other `unreachable` exists. A user `Raise`
  is `fail_with_error(code); drop` and NOTHING more — if the function tail
  follows a `Raise`, the tail guard sequence after it is dead code and
  permitted.
- **Host functions by NAME** (B1): `serpent._host.functions_by_name`; export
  codes are data. Per-arg Val-typedness from `HostFn.val_typed_args`, wasm
  types from `wasm_params`/`wasm_result` (B2) — never re-derived.
- **Two host-fn accounting rules (amended per review M4/M5):** imports are
  emitted ONLY for functions the lowered code actually calls — a subset of
  `host_fns_reachable ∪ OMITTED_FAMILIES`, where `OMITTED_FAMILIES` is the
  pinned-ungated set C deliberately omits (the small/object bridges, the
  128-piece constructors/accessors, the i256 div/rem family, the
  Timepoint/Duration bridges — C3) plus D's own additions (`fail_with_error`
  on overflow paths, `bytes_len` for `BytesN` prologues, the E13 and B6-fix
  names). The safety net: a test recomputes
  `declared_protocol(emitted_import_names, target)` and asserts it equals
  the declared value (F.2.11) — sound because every OMITTED_FAMILIES member
  is pinned ungated.
- **env-meta carries `compiled.declared_protocol`** — the computed floor when
  no target was requested, the requested target when one was (that is
  `declared_protocol`'s own contract, B4; "users may raise, never lower",
  S6) — straight into `build_env_meta` (E9).
- Reserved runtime error codes from `serpent.errors` (C19), by import: never
  restate the values. Prologue failures → `CODE_ABI_CHECK_FAILED`; overflow →
  `CODE_ARITHMETIC_OVERFLOW`; missing storage key → `CODE_MISSING_VALUE`;
  diverging tail → `CODE_UNREACHABLE_GUARD`; not-yet-lowered →
  `CODE_UNSUPPORTED_AT_RUNTIME`.
- Error split (E15, sharpened per review M10): `EmitError(Exception)` is the

    `r = i64.mul(a, b)`, overflow iff `a != 0 and i64.div_u(r, a) != b`;

    a host call). Signature there.

    `{u,i}64_<op>`; `Unary(NEG)` on U64/I64/U32/I32 → nothing (inline); on

    exact sets AND `runtime_parts_needed ⊆ parts D links` is tested in
