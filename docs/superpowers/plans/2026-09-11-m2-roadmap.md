**Spec:** `docs/superpowers/specs/2026-08-26-serpent-python-soroban-sdk-design.md` §11
("M2 -- reach. Cross-contract calls (`call`/`try_call` + typed client stubs consuming

M2's goal (spec §11): reach -- the parts of the Soroban host a real contract needs
beyond storage/auth/events: talking to other contracts, hashing and signature
verification, randomness, deploying and upgrading, the wide integers, plus the
tier-1 fidelity and testing ergonomics that the M1 close showed users expect.
Honest sizing: M2 is comparable to M1-C..F in effort (five sub-plans, each 8-12
tasks). Every sub-plan leaves `main` green and independently useful.

**Order and why:** A -> B -> C -> D -> E. B needs A's `current_contract_address` and
`sha256` (deployer salts, the token's contract identity) and is the headline risk of
M2, so it follows A directly rather than waiting on C. C is independent of B (SEP-41
uses I128, which exists). D's ergonomics build on B's typed-client design. E closes.

**Standing constraints for every sub-plan** (unchanged from M1): single Val codec;
validate-inside-compiler; error codes never lost to `unreachable`; the zero-dep core
(`tests/unit/test_core_zero_dep.py`); the frozen, append-only SPT registry (new codes
by controller sanction only, pins in the same commit); the four gates plus the Rust
gate and `mkdocs build --strict` on every task; every sub-plan gets a dossier, an
adversarial plan review before execution, subagent-driven development with
task-scoped reviews, and a Fable whole-branch final review; local merge to main, no
pushes.

**The byte freeze (M1-G ruling M13) still binds M2:** no edit may move an emitted byte
of `examples/shapes.py` or `examples/bounty_board.py`; the byte-equality tests pin
HEAD's build of each to its deployed bytes. Any A-E change to a lowering those two
examples reach (hashing, symbol handling, the ABI prologue, the runtime parts) is a
controller decision, and the deployed-bytes tests are the tripwire. The guestbook is
NOT deployed and may move.

**Signing for the M2 run:** Elliot is away; `commit.gpgsign` is locally `false` for
the run and a `post-commit` hook logs every unsigned sha to
`.git/unsigned-commits.log`. The M1-G run (903e16b..083c699, and v0.1.0 on 083c699)
was never re-signed, so ONE rebase from 11de4bd re-signs both runs; the tag then
moves to the re-signed commit.
