### B.4 Checked-arithmetic lowerings, per width (S4/A4)

The contract to reproduce **exactly**: out-of-range → `fail_with_error(error_val(CODE_ARITHMETIC_OVERFLOW))`, never wrap; `//` truncates toward **zero**; `%` takes the **dividend's** sign; `MIN % -1 == 0` (not a trap); `//0` and `%0` trap (A4).

**The i256 div/rem route, verified live against the pin.** `obj_from_i256_pieces` (`i.g`, args `('i64','u64','u64','u64')` → `I256Object`), `i256_div` (`i.y`, `(I256Val, I256Val) → I256Val`), `i256_rem_euclid` (`i.z`), `obj_to_i256_hi_hi/hi_lo/lo_hi/lo_lo` (`i.j`–`i.m`); unsigned twins `obj_from_u256_pieces` (`i.9`), `u256_div` (`i.q`), `u256_rem_euclid` (`i.r`), `obj_to_u256_*` (`i.c`–`i.f`). **All ungated (`min_protocol=None`)** — which is what makes C3's omission floor-safe. **There is no `i256_checked_div` or `u256_checked_div` in the pin at all** [verified live] — the `i256_checked_*` family is `add/sub/mul/pow` only, gated at protocol 26; `i256_div`'s own docs already say "**returning `ScError` if `rhs == 0` or overflow occurred**", so the unchecked name *is* the checked operation.

**⚠ `i256_rem_euclid` is EUCLIDEAN, not truncated.** Verified live from the binding's own docs: "Performs checked **Euclidean** modulo. Computes `lhs % rhs`". A4 requires `%` to take the **dividend's** sign (Python/Rust truncated semantics for `//` paired with a sign-following `%`… see F.1.2). D **cannot** route `i128 % ` straight through `i256_rem_euclid` — it must post-correct the sign, or compute `rem = lhs - (lhs // rhs) * rhs` from `i256_div`. This is the single most consequential arithmetic finding in this dossier.

### B.5 Where the shipped IR differs from the M1-C dossier's §C.2 proposal

The shipped code wins (task instruction; D13's own precedent). Differences a planner reading only the M1-C dossier would get wrong:

1. **Two host-fn sets, not one.** The dossier's §C.2 output 1 was `host_fns_used: frozenset[str]`. Shipped: `host_fns_used` **and** `host_fns_reachable`, with **the protocol floor computed over reachable** (D13, `frontend.py:41-56,313-314`).

### C.1 Emitter architecture

**Module layout.** Mirror the frontend's shape: one small module per concern, all importing shared node definitions, so no two files can hold slightly different ideas of the same thing (`ir.py`'s own stated rationale, lines 1–8).

```
src/serpent/emitter/
  __init__.py      # public: build_wasm(...) / BuildResult  (§C.2)
  encode.py        # uleb / sleb / vec / section / wasm_name / custom_section  (P18, copied not imported, R5)
  opcodes.py       # every opcode + valtype constant, ONE definition each, with a
                   #   provenance comment per line: "on-chain-verified (P17)" or
                   #   "core binary format, pinned by test_opcodes.py"
  layout.py        # Memory: literal pool (interned) + compile-time scratch bump  (P12)
  frame.py         # Fn: the operand-stack + control-frame tracker  (P13)
  validate.py      # the INTERNAL validator + the wasm-tools shell-out  (S2/S7)
  lower.py         # IR node -> instructions  (§B.3)
  arith.py         # per-width checked arithmetic  (§B.4)
  runtime/         # the guest runtime library parts  (§E2 decides the form)
  sections.py      # the three custom sections, delegating to serpent.spec  (B7/B8/B11)
  module.py        # section assembly + the M13 assertion + size guard  (§B.1, P11, P15)
```

**Operand-stack validator.** Port `_Fn`/`_Ctrl` by copy (R5) and extend:

- Keep verbatim: typed `push`/`pop` with a named type string, `unreachable` mirroring wasm's polymorphic-stack rule, `_check_frame` at both `else` and `end`, `entry_unreachable` restored by the frame's end, **the balance check at `ret()` not at `finish()`** (P2 — the single most important line in the whole tracker), and `EmitError` as an exception rather than an `assert` "so the checks survive `python -O`" (`emitter.py:93-98`).
- Extend for D's larger language: `block`/`loop` frames with a **label kind** (so `Break`→`block` and `Continue`→`loop` compute the right `br` depth from the frame stack rather than from an ad-hoc counter — this is where an off-by-one becomes a silently wrong branch); a **br-target arity check** (a `br` to a frame with a result type must leave that value on the stack); and a **`local index < declared count`** check.
- Add what the spike could not have: an assertion that the value model holds — **every expression lowering leaves net +1 `i64`** — checkable by wrapping every `lower_expr` call in a height delta assertion. This is the cheap structural version of S2's "asserts at every control-flow merge".

**Function index space.** Imports occupy `[0, n_imports)`; defined functions `[n_imports, n_imports + n_funcs)`. Proposal: **import order = `sorted(host_fns_reachable_actually_emitted)`** (the spike's `sorted(host_fns)`, `emitter.py:520`) and **defined order = `CompiledModule.functions` order** (contract methods in source order — `__constructor` wherever `__init__` was declared — then helpers). Both are deterministic and independent of dict iteration order (§E7). Note: emit an import **only if it is actually reached by the emitted code**, which is a subset of `host_fns_reachable` once D has made its form choices — S6 says the declared protocol is over "imports actually emitted", and an unused import is dead bytes plus a false protocol input.

**Literal pooling.** `layout.Memory.intern(blob, align=1)` exactly as P12, seeded from `CompiledModule.literals` in its already-sorted order so the pool is deterministic, then extended on demand for struct key blobs. Proposal: **pre-intern the whole `LiteralInventory` up front, in inventory order**, before lowering any body — that makes pool offsets a pure function of the inventory, which is what makes byte-reproducibility (§E7) testable without threading emission order through everything.

**Two-pass structure.** The spike compiles every body (and checks every stack) **before laying out a single byte** (`emitter.py:816-826`). Keep that: pass 1 lowers all bodies and finalizes the pool/scratch; pass 2 assembles sections. This is what makes "an invalid module is a compile error, never an output file" (S2/P8) structural rather than a convention.

### D.5 Fuzz

1. **Round-trip fuzz on the encoder**: random `(n, align, offset)` through `uleb`/`sleb`/`section`/`vec`, asserting minimal-length encodings and decode round-trips.
2. **IR fuzz → validator**: generate random *well-typed* `FuncIR`s from the node grammar (the IR is frozen dataclasses, so a Hypothesis strategy per node kind is mechanical) and assert every one either emits a module that passes the internal validator **and** `wasm-tools validate`, or raises `EmitError` — **never** produces bytes that fail validation. This is D's analogue of C's "any `ast.parse`-valid random Python must produce a `CompileError`, never an internal traceback" (M1-C §F.2.5).
3. **Source-level fuzz through the whole pipeline**: reuse C's existing fuzz generators (attention file line 17 notes their known coverage gap: they "never spell `env.ledger()`/`temporary()`/`extend_ttl`/`require_auth_for_args`/most container methods") — **D should close that gap rather than inherit it**, since those are exactly the lowerings D adds.
4. **Arithmetic fuzz against Python**: for every width and every op, random operand pairs compared against Python's arbitrary-precision answer *plus* A4's rules (truncating `//`, sign-following `%`, `MIN % -1 == 0`, overflow → the exact error code). This is the cheapest high-value test in D and needs no engine for the *expected* side.

## E. OPEN QUESTIONS FOR THE CONTROLLER

Sixteen questions. Each has options and **one** recommendation with evidence. The dossier recommends; the controller rules.

**E1 — D's execution-test harness (the biggest question in D).**
Forces: `wasm-tools validate` provably cannot catch a leaked operand (P2); S7 makes instantiation under a real host the release gate; S18 demands the semantics table run against compiled WASM; S15 demands each runtime part be "differential-tested against the real host"; but tiers are row F and A→D is sequential (R4). Options: **(a)** a minimal wasmtime-py dev-only harness inside D's tests — pinned `Config` with `relaxed_simd` before `simd` (P3/R3), single-trampoline u64 masking over every callback (P4), implementing only the host functions D's examples import; **(b)** resurrect the spike mini-host patterns by copy (R5) — same as (a) but seeded from `spikes/spike1/harness.py`, minus its stale object bound (A8); **(c)** pull tier-2b (PyO3 real host) forward into D; **(d)** defer all execution proof to F.
Evidence that shifts (a)/(b) from "nice" to "cheap": **`wasmtime==48.0.0` is already a dev dependency and is already installed by `uv sync --all-groups` in CI [verified live]** (E2) — so (a) adds *zero* new dependency and *zero* CI change. Against (c): P6's own open item is that the real host's protocol ceiling is compiled in, making the wheel matrix platform × Python × protocol — a distribution decision D should not be forced to make, and one CI cannot satisfy on three Python versions without prebuilt wheels. Against (d): it makes the emitter's correctness unproven at merge, which R4 says cannot be repaired later.
**Recommendation: (b) — a D-local wasmtime mini-host, ported by copy from the spike, with F productizing it.** Rationale: it is the option with no new dependency, it reuses on-chain-corroborated code (the same eight host functions produced verified testnet behavior, findings §1 row 8), it inherits the two hard-won correctness details (P3's ordering, P4's structural masking), and it lets D run the ~38 in-scope semantics cases at merge. Explicitly *not* claimed: fidelity — the spike's own docstring says "A green run here means 'the codegen is self-consistent', not 'this contract is correct on chain'" (`harness.py:18-21`). Pair it with a **named, tracked obligation** that F re-runs the same table on tier 2b, and record in D's plan that the mini-host is **not** an oracle.

**E2 — Runtime-parts form: what does "pre-assembled WAT" mean mechanically?**
S12's heading says "pre-assembled WAT" and the body says "small hand-written WASM function bodies, **assembled once**". That is a design-era description of the AssemblyScript stub-runtime *pattern*, written before the emitter existed; it is not obviously a mandate on mechanism, but it is the spec's word and the controller should say so explicitly. Options: **(a)** check in assembled bytes, with the WAT source kept beside them as reviewed documentation plus a drift test that re-assembles and compares (requires `wat2wasm`/`wasm-tools parse` at *dev* time only); **(b)** write a tiny in-repo WAT assembler for the needed subset; **(c)** **no WAT at all** — emit the parts from the same Python encoder as everything else, as ordinary `Fn` bodies built by `arith.py`.
**Recommendation: (c), with the WAT spelling kept in a docstring per part as human-readable documentation.** Evidence: S1 pins "hand-rolled encoder" as the pipeline; (a) and (b) both add a second code path into the same bytes, which is exactly the "two implementations of one semantics" drift S18 names as the highest internal risk; (c) means the runtime parts go through the *same* operand-stack validator as user code (S2 applies to them too, and they are the hairiest code in the module); and (c) is the only option that needs no new tool. Cost to accept explicitly: nobody can eyeball a runtime part as WAT unless D also ships a disassembling printer — which §D.2's disassembly goldens want anyway. Flagging for the controller: this is a **deliberate re-reading of the spec's §6 heading**, and if the controller wants the heading honoured literally, (a) is the option.

**E3 — Ratify or rename `runtime_parts_needed`, and settle the full part inventory.**
C's 13 coined names are `overflow_check` + `{u128,i128}×{add,sub,mul,floordiv,mod,neg}` (C2). Gaps found (§B.6): no **i128 compare** part despite S13 naming it; no **tag-check prologue helper** despite S14; no **small-val boxing/unboxing** despite S14 and despite it being needed for every `U64/I64/U128/I128/Timepoint/Duration` value; no **host-call-return narrowing** part despite S3; and one `overflow_check` name standing in for what is really one helper per (width, op-class).
**Recommendation: ratify the 13 names as-is (they are honest and already tested) and EXTEND the set in the same commit series, per C2's explicit licence, to: `overflow_check_u32`, `overflow_check_i32`, `overflow_check_u64`, `overflow_check_i64` (keeping `overflow_check` as an alias only if a test depends on it — otherwise renaming is cleaner while there are zero consumers, D13); `{u128,i128}_cmp`; `box_u64`/`unbox_u64`/`box_i64`/`unbox_i64`/`box_u128`/`unbox_u128`/`box_i128`/`unbox_i128`; `tagcheck_<ty>` per checked type; and `narrow_<ty>`.** Which widths need a guest helper vs an inline sequence: **U32/I32 inline** (a shift, an op, a range compare — cheaper than 74 instructions of call overhead, S25); **U64/I64 helper** (the unbox branch is 6+ instructions and appears at every use); **U128/I128 helper always** (S13's whole premise); **div/rem for 128-bit via the i256 host route** (S13), entering at `{u128,i128}_floordiv`/`_mod` and reaching `obj_from_{i,u}256_pieces` + `{i,u}256_div` + a **sign-corrected** remainder (see E16/F.1.2). Also ratify: `runtime_parts_needed` becomes documented as **a hint, not a manifest** — D links from its own lowering, and a test asserts `runtime_parts_needed ⊆ runtime_parts_linked`.

**E4 — ABI-prologue failure codes, and reconciling the trailing `unreachable` with S7's "never a bare `unreachable`".**
The apparent conflict: C1 says D **must** emit a trailing `unreachable` for a diverging body; S7/R3 say error codes are **never** lost to `unreachable`; C19 allocates `CODE_UNREACHABLE_GUARD` for "a defensive `fail_with_error` the emitter inserts after … a definite-return-proven function tail". They reconcile cleanly once you separate the two positions:
- **Position 1 — after `fail_with_error`:** emit **nothing**. P14 is explicit and on-chain-verified: "an `unreachable` after it would replace the contract error the client needs to see with a generic VM trap". `drop` the Void Val for frame balance and stop.
- **Position 2 — a genuinely-diverging function tail** (C1's `while True:` with no `break`): there is no error to preserve, and the code is provably dead. Two sub-options: **(i)** bare `unreachable` (0x00); **(ii)** `fail_with_error(CODE_UNREACHABLE_GUARD)` then `unreachable` — the guard fires first if the "provably dead" proof was wrong, and the `unreachable` satisfies the validator.
**Recommendation: (ii), in that order — `fail_with_error(CODE_UNREACHABLE_GUARD)` THEN `unreachable`.** It is exactly what C19's documented duty says the code is for; it turns a compiler bug into a distinct on-chain-readable code instead of an information-free trap (the same argument S4 makes for `ArithmeticOverflow`); it satisfies R3 in letter and spirit (the only `unreachable` in the module is preceded by a code); and the size cost is ~12 bytes per diverging function, of which real contracts have approximately zero. On the prologue code itself: **use `CODE_ABI_CHECK_FAILED` (0xFFFF_FFFB), one code for every argument position, as C19 documents** — and record in D's plan that this **differs from the on-chain artifact's `0xFFFF_FFFF`** (P16), so the code section is legitimately not byte-comparable to it (S8 already forbids that comparison anyway).

**E5 — `wasm-tools` as an external validation dependency.**
S7 wants it as a fast pre-check; S2 says "plus `wasm-tools validate` **when available**"; it is a Rust CLI, **absent from `pyproject.toml` and from CI [verified live]**, and CI already has no `stellar` CLI (`tests/goldens/README.md:62-63` records a test that skips when it is missing, "never silently passed"). Options: **(a)** hard requirement (build fails without it); **(b)** optional-if-present, with the internal validator as the always-on gate; **(c)** drop it entirely in favour of the internal validator + tier-2 instantiation.
**Recommendation: (b), with three specifics.** (1) The **internal validator is unconditional and is the compile-time gate** (S2's "validation runs *inside* the compiler"). (2) `wasm-tools` runs when found on `PATH`, with the exact feature string `-all,mutable-global,sign-extension,bulk-memory` **as a named constant with the S23 citation beside it** (P8). (3) In D's *tests*, the wasm-tools check is a `pytest.mark.skipif(shutil.which("wasm-tools") is None)` — **skipped, never silently passed** (the established precedent) — and CI additionally installs it in one job so the check actually runs somewhere; pin the version and add a drift test (R3's "pinned toolchain versions with drift-detection tests"). (a) is wrong because it would make `pip install serpent && serpent build` fail on a machine with no Rust toolchain; (c) throws away a real independent check for nothing.

**E6 — The public API shape D ships.**
Options: **(a)** `serpent.build(path)` at the package root; **(b)** `serpent.compiler.build_wasm(compiled)` beside `compile_module`; **(c)** a new `serpent.emitter` subpackage with `build_wasm` + `build_file`, re-exported as `serpent.build` for convenience.
Forces: `serpent.__all__` is pinned by `tests/unit/test_public_api.py` and is the **authoring** surface a contract resolves names against (M1-C A22) — adding a build function to it would put a build API into the namespace contracts are checked against. G owns the CLI. D9 keeps the core zero-dep, and the emitter needs `serpent.spec` (hence `stellar_sdk`) for the custom sections.
**Recommendation: (c) — `src/serpent/emitter/` exporting `build_wasm(compiled, …)` and `build_file(path, …)`, NOT added to `serpent.__all__`.** It mirrors `serpent.compiler`'s own precedent exactly (a subpackage with a small public surface and a documented zero-dep-walk position, `src/serpent/compiler/__init__.py:1-13`), it keeps the authoring namespace clean, and `sandbox/compile.py`'s successor calls `build_file` in one line. Name the module `emitter` rather than `build` because the roadmap and spec both call this thing "the emitter", and row D's deliverable phrase "`serpent build`" refers to the *command*, which is G's.

**E7 — Determinism: byte-reproducible output as a tested guarantee?**
Options: **(a)** yes, tested; **(b)** best-effort, untested; **(c)** no guarantee.
Evidence for (a): every input is already deterministic — `LiteralInventory` tuples are "deduplicated and sorted, so the inventory is a property of the module rather than of the order the checker happened to walk it" (`frontend.py:199-201`), `spec_inputs.declared_types_in_order` is declaration order (B8), `functions` is source order, and the spike's import order was `sorted()`. The only nondeterminism risks are set iteration (`frozenset` ordering is hash-dependent), dict iteration in the type-section dedupe, and non-minimal LEB encodings. Downstream, `sha256(wasm)` **is** the on-chain `wasm_hash` (findings §1: "the on-chain `ContractInstance.executable.wasm_hash` is that same digest"), so reproducibility is directly user-visible and is what lets anyone verify a deployed contract against source.
**Recommendation: (a) yes, with this test shape:** a test that builds each example twice **in separate subprocesses with different `PYTHONHASHSEED`** and asserts byte equality (a same-process double build would not catch hash-order dependence); plus a lint-style test that every `frozenset`/`set` reaching the emitter is sorted at the boundary; plus a property test that `uleb`/`sleb` are minimal-length. Cost to accept: reproducibility becomes a compatibility promise, so any later change to pool ordering or index assignment is a visible artifact-hash change — which is the point.

**E8 — Does D emit `contractmetav0` by default, and what is `serpentver` pre-release?**
S16 lists `contractmetav0` with `name`, `version`, `serpentver` plus user pairs; S8 says it is **never byte-compared**; the spike emitted `{"serpent": "0.0.1-spike1"}` (`build.py:76`). `pyproject.toml:3` says `version = "0.0.1"`.
**Recommendation: yes, by default, with three keys — and make the version derived, not written.** `serpentver` = `importlib.metadata.version("serpent")` (i.e. `0.0.1` today), so it cannot drift from the package; `name` = the `@contract` class name (`ir.contract.name`); `version` = **omitted unless the caller supplies it** (`--meta version=…`), because inventing a contract version number the author did not state is a lie in a section tools read. Plus every `--meta k=v` pair. Add a test that the section decodes and that `serpentver` matches the installed distribution — and record that S8 forbids a byte golden here, so the test must be structural.

**E9 — Floor-vs-target: what goes into `build_env_meta`?**
The tension is real and now measured. B4 says `declared_protocol(...)` "is THE value D writes into `build_env_meta`", and with `requested is None` it returns the **computed floor**. S6 says "declared protocol is computed, never hand-set … Users may raise the declared protocol, never lower it below the computed floor." But **the on-chain Phase 0 artifact declares 27** while its import floor was 20 (P9), and **`sandbox/counter.py` computes 20 [verified live]** — so a serpent-built counter today would declare `20` where the spike declared `27`. Options: **(a)** write the computed floor (what `compile_module` already returns); **(b)** write the build target, defaulting to `DEFAULT_TARGET_PROTOCOL = 27`; **(c)** write the floor, but make the target an explicit, prominent build option that is *recorded in the build report*.
What declaring 20 actually means: `contractenvmetav0`'s `protocol` is the **interface version the contract was built against**; a host at protocol 27 accepts a module declaring 20 (that is the whole point of the floor), and declaring the floor maximises the set of networks the artifact runs on. Declaring 27 would make the same bytes *fail* on a protocol-26 network for no reason.
**Recommendation: (a)/(c) — write the computed floor, i.e. pass `compiled.declared_protocol` straight to `build_env_meta`, and surface both numbers in `BuildResult` and in the CLI's build line** (the spike's own output format already did this: `env-meta protocol=27 (import floor=20)` — invert it to `env-meta protocol=20 (build target=27)`). This is the reading S6 and B4 both literally require; `target_protocol` stays where C put it (a *gate* on which functions may be reached, `frontend.py:288-291`), which is its actual job. **Explicitly flag to the controller:** this means D's artifacts declare a *lower* protocol than the Phase 0 artifact did, so any test comparing env-meta bytes against `spikes/spike1/spike.wasm` must compare against `env_meta(20)` for a serpent-built module, and the existing on-chain-verified `env_meta_27.bin` golden stays a golden of the *builder function*, not of a D artifact.

**E10 — Memoryless emission: omit the memory entirely, or always declare one?**
S11 requires memoryless modules to still compile ("the size win stays"); C's `needs_memory` over-approximates (C21). Options: **(a)** omit sections 5 and 11 and the memory export whenever `needs_memory=False`; **(b)** always declare and export one memory (simpler, always M13-safe); **(c)** decide from D's *own* post-lowering fact (did the pool end up empty and was no LM host fn emitted?) rather than from C's flag.
**Recommendation: (c), with (a) as its observable behaviour.** D knows more than C does — after lowering, D knows exactly which host functions it emitted and whether the pool is empty, so it can be *precise* where C could only be conservative, and it can assert `needs_memory=False ⇒ D also concluded no memory` (a mismatch in the other direction is fine and expected, C21). (b) throws away the size win S11 explicitly preserves; the counter class is the flagship small artifact (344 B on chain, S27).

**E11 — Lowering `ConstRef` and void `InternalCall`s.**
Two small shape questions with no precedent in the spike. (i) `ConstDecl`/`ConstRef` (module-level chain constants like `ADMIN = Symbol("ADMIN")`, live in `tests/goldens/ir/memoryless.ir.txt`): options are inline the constant's `value` expression at every use, or materialise it once per function into a hidden local, or add a globals section. (ii) An `InternalCall` to a `-> None` helper: options are type the internal function as `→ ()` (0 results) or as `→ (i64)` returning a Void Val.
**Recommendation: (i) inline at every use** — a module constant is by construction a `Const` or a small constant expression, inlining keeps the function index space and the local tables simple, and a globals section would be the only reason to enable `mutable-global` output (B.1). If a constant is a *pooled literal* (a long `Symbol`, a `String`), inlining means one `symbol_new_from_linear_memory` call per use, so **add a per-function memoisation into a hidden local when a pooled `ConstRef` appears more than once in one function** — measurable at 74 instructions per avoided host call (S25). **(ii) type internal void helpers as `→ ()`** and let `Eval` need no `drop`; it is smaller and the frame tracker already handles void frames. Cost: exports still must be `→ (1×i64)` (S23), so the type section carries both shapes — which is fine and already deduped.

**E12 — `MakeMap(all_static=True)` with non-`Symbol` keys.**
C sets `all_static=True` when the literal pairs are in host key order with unique keys (`ir.py:369-374`), *independently* of key type. But `map_new_from_linear_memory` takes **key descriptors that "must be byte strings … convertible to `Symbol` type"** (P1, verified live from the binding docs) — so the LM form is unavailable for a `Map[U32, …]` literal however static it is. Options: **(a)** D gates the LM form on `key_ty.tag is SYMBOL and every key is a Const` and falls back to `map_new`+`map_put` otherwise; **(b)** ask C to narrow `all_static` to mean LM-eligible; **(c)** always use `map_new`+`map_put` for maps.
**Recommendation: (a).** It needs no frontend change (D13's whole point is that D owns the form choice), it is exactly the C4 discipline generalised ("`all_static` is a fact about the ITEMS, not a licence to lay them out"), and (b) would overload one flag with two meanings. Add a test with a `Map[U32, U32]` literal asserting the build-up chain is used. Note the same question does **not** arise for `MakeVec`/`MakeTopics`: `vec_new_from_linear_memory` takes "an input slice of **Vals**" (verified live), so any IMMEDIATE-repr element works.

**E13 — Storage `get(key, T)` with no `default`: whose error?**
C19 says `CODE_MISSING_VALUE` is emitted by "the storage `get(key, T)` lowering (no `default`) **when the host reports the key absent**". But the IR for that form is a **bare `HostCall("get_contract_data")`** with no `has_contract_data` beside it, and **`host_fns_used` for such a contract is exactly `{get_contract_data}` [verified live on a scratch probe]** — so if D emits `has_contract_data` + branch + `fail_with_error`, it reaches two host functions in **neither** C-provided set. Options: **(a)** let `get_contract_data` trap on a missing key (a host `Storage` error), never emitting `CODE_MISSING_VALUE` for this form — and re-scope `CODE_MISSING_VALUE` to whatever else needs it; **(b)** emit the `has`-then-`get` guard and raise `CODE_MISSING_VALUE`, accepting two extra out-of-set host fns (both ungated, so floor-safe by C3's own argument); **(c)** ask C to add both names to `host_fns_used` for the no-`default` `get`.
**Recommendation: (b) + (c) together.** (b) because a contract-readable code is strictly better than an information-free host error (S4's argument again) and because A10's exception-mapping rule puts "missing key" on the *contract error* side of the line C19 already drew; (c) because leaving two emitted imports out of `host_fns_used` breaks the property that the set describes the module — a one-line frontend change in D's commit series, exactly as C2 permits for `runtime_parts_needed`. **Whichever the controller picks, D must add the corresponding pinning test**: either `CODE_MISSING_VALUE` is emitted and both names appear in the import section, or `CODE_MISSING_VALUE` is documented as not-yet-emitted (mirroring `NO_FIXTURE_ALLOWLIST`'s honesty discipline, D15).

**E14 — ABI-prologue coverage and cost.**
S3 is unambiguous that the prologue is non-negotiable and that host-call returns narrower than `Val` are checked the same way; the measured cost was `add(Symbol('hello')) → 45` (S3), and S25 prices instructions at 4 units each. The spike checked only `U32` params and "is measuring the shape of the check, not its coverage" (P16). Options: **(a)** tag check only, per param; **(b)** tag **and range** check per param (S3's literal words), i.e. for `U32` also verify the minor field is 0, for `BytesN(n)` verify the length, for `Option` accept `Void` or the wrapped tag; **(c)** (b) but factored into shared `tagcheck_<ty>` runtime helpers to amortise size.
**Recommendation: (b), inline, with (c) applied only where a type's check exceeds ~8 instructions** (the break-even against 74 instructions of call overhead, S25 — meaning `Struct`, `Vec[T]`, `Map[K,V]` and `BytesN(n)` get helpers; `Bool`/`U32`/`I32`/`Address`/`Symbol` stay inline). Also: **the narrowing check on host-call returns is the same code path** and must not be forgotten — `get_contract_data` returning `Struct(Settings)` (live in `tests/goldens/ir/spike1_reauthored.ir.txt`) is precisely S3's second sentence, and it is the check that turns a corrupted ledger entry into a contract error instead of a mis-typed map read. Document the size/CPU cost in the docs, as S4 requires for the arithmetic checks.

**E15 — How does D report failures: `EmitError` or the `SPT####` registry?**
C17 gives D a complete located-diagnostic infrastructure, and the sink **rejects unregistered codes**. But most emitter failures are *compiler bugs*, not user errors (an unbalanced stack cannot be caused by a valid contract, since C proved the program well-formed). Options: **(a)** everything through `Diagnostics`/`CompileError` with a new `SPT8xxx` band; **(b)** everything through an `EmitError(Exception)` like the spike; **(c)** split by cause — user-visible facts get located `SPT8xxx` diagnostics, internal invariant breaks get `CompilerBugError` (the existing `AssertionError` subclass, deliberately not catchable with `CompileError`, `frontend.py:292-298`).
**Recommendation: (c).** The user-visible set is small and genuinely located: module exceeds 131072 bytes (S22, cite the contract); literal pool overflows into scratch or scratch exceeds one page (P12); an export arity/name problem the frontend could not see; a construct the emitter does not yet lower (paired with `CODE_UNSUPPORTED_AT_RUNTIME` at runtime, C19). Everything else — stack imbalance, open frames, bad `br` depth, a host-fn name the pin lacks — is `CompilerBugError`, which is what the frontend already does for exactly this class (`frontend.py:549-560`). Register the `SPT8xxx` rows under D15's append-only discipline.

**E16 — `i128`/`u128` comparison: runtime part, inline, or `obj_cmp`?**
C sets `via_obj_cmp=False` for `U128`/`I128` (C6), so C is telling D "compare on the narrowed type". S13 names "compare" as a guest runtime part. But `obj_cmp` exists, is ungated, and answers structurally for any Val pair. Options: **(a)** a `{u128,i128}_cmp` guest part comparing the limb pairs (hi first, then lo unsigned); **(b)** inline the two-limb compare at each site; **(c)** route through `obj_cmp` anyway (ignoring `via_obj_cmp=False`, which is permitted — the flag forbids the *raw-Val shortcut*, it does not mandate a scalar compare).
**Recommendation: (a).** S13 names it, the limb compare is ~10 instructions and appears at every 128-bit comparison so a helper amortises (S25), and (c) costs 74 instructions of dispatch overhead plus a `VisitObject` per operand for something guest code does trivially — while also being the option most likely to disagree with tier 1 for a *small*-form 128-bit value. Correctness note for whichever is chosen: the operands must be **unboxed first** (F.1.1), and the signed compare must be `hi` signed, `lo` unsigned.

## F. RISKS

### F.1 Where D can silently diverge — from the tier-1 oracle, or from the on-chain host, with no error anywhere

Ordered by likelihood × silence. Every entry's failure mode is "validates, deploys, and is wrong".

| # | Divergence | Why it is silent | Mitigation |
|---|---|---|---|
| **1** | **A raw-Val compare for an `EITHER`-repr numeric.** `Compare.via_obj_cmp=False` for `U64 I64 U128 I128 Timepoint Duration` (C6), and `ir.py:268-271` says that means "a direct scalar compare **on the narrowed type**". Read as "compare the two Val words", it is catastrophically wrong: an `I64` small Val is `(two's-complement-56-bit << 8) \| 7`, so `-1` becomes `0xFFFF_FFFF_FFFF_FF07` and compares *greater* than `+1`; an object-form Val is `(handle_index << 32) \| tag`, so `U64` object handle 0 is the word `64` while the small `U64(100)` is `25606` — **the object compares less than the small**, inverting order at the 2⁵⁶ boundary. | Both `>` forms compile, validate, and return plausible booleans. Small-value test cases (which is what unit tests naturally use) **stay inside the small form and pass**; the bug appears only above 2⁵⁶ or below zero. | Unbox to the declared width before every scalar compare; a differential test with operands straddling `MAX_SMALL_U64` and `MIN_SMALL_I64` (A5's constants) in **both** directions; assert in the lowering that a compare's operand is a numeric, not a Val. |
| **2** | **`%` via `i256_rem_euclid`.** The binding's own docs say "**Euclidean** modulo" [verified live]; A4 requires `%` to take the **dividend's sign** (`-7 % 2 == -1`, not `+1`). Euclidean gives a non-negative remainder. | Every non-negative operand pair agrees. `-7 % 2` disagrees, and tier 1's answer is the frozen one. | Compute `rem = lhs - (lhs // rhs) * rhs` from `i256_div`, or post-correct the sign; a fuzz test over signed operand pairs against Python's `%` (D.5.4); a dedicated case for `MIN % -1 == 0` (A4) and for every sign combination. |

C already sorted (C9) — the risk is D re-sorting, reordering, or writing Val words instead of descriptors, or writing the *values* array in a different order than the keys. | `wasm-tools validate` passes. A mini-host that does not enforce the ascending invariant passes too — which is why the spike's harness enforces it explicitly, "because an emitter that stopped sorting would otherwise pass this harness and fail only on chain" (`harness.py:246-248`). | Never re-sort `MakeStruct.fields`; assert the emitted descriptor order matches the node's field order; **keep the mini-host's ascending-key check** (port it, E1); a golden on the emitted key blob for `Settings`. |
| **6** | **A leaked operand.** P2, verbatim and on-chain-corroborated: a leaked operand **passes** `wasm-tools validate` because `return` is polymorphic. | No validator anywhere catches it. The leaked Val is simply lost; on chain it costs budget and may shift a later result. | The balance check at `ret()`, not at `finish()` (P2/R3); the RED-proven failure tests (D.1.1); the net-+1 assertion per expression lowering (§C.1). |
| **7** | **Missing trailing `unreachable` for a diverging body (C1).** This one is *loud* at validation — but only if D actually validates every function, including one with an unreachable tail that a golden-only test would never exercise. | Fails validation, so not silent — but the *inverse* error is: emitting `unreachable` **after `fail_with_error`** (P14) IS silent, and replaces a contract error code with a generic VM trap. Clients then see a trap where they expected code 7. | The two positions kept strictly separate (E4); a test that no `unreachable` follows a `fail_with_error`; the on-chain evidence for code 7 (findings §1 row 6) as the acceptance criterion. |

D's temptation is the obvious optimisation — a raw i64 compare of two SymbolSmall immediates — which flips the answer. | Both are immediates; the raw compare is one instruction vs 74; every same-case Symbol pair agrees. Only `_`-vs-letter pairs disagree. | Never take the shortcut; `cases.py:symbol_underscore_vs_A_ascii_order` run against compiled WASM (D.4); if the host disagrees with tier 1, that is a **controller decision on the frozen table**, not a reflag. |

A peephole optimiser that folds constant arithmetic would make that semantics case unreachable and silently reclassify it. | The test would *pass differently* (a compile error instead of a runtime code) and someone would "fix" the table. | No arithmetic constant folding in D either; state it in the plan; the semantics case is the tripwire. |

### F.2 Differential checks that belong in D's own test plan

1. **The ~38 in-scope semantics cases run against compiled WASM** (S18/D.4) — the headline obligation, and the only thing that closes the S18 drift risk.
2. **`spike1_reauthored` end-to-end**: compile → build → validate → run in the harness → assert the recorded on-chain behaviour (`setup(3)`; `bump()`×3 → 1, 2, 3; the 4th → contract error **code 7** discriminated as `SCE_CONTRACT`, P7). This is the one place D can check itself against a *live-network-observed* behaviour sequence (findings §1 rows 5–6).
3. **Import-set anchor**: the emitted import section for `spike1_reauthored` equals the eight names the 877-byte artifact carried (already pinned frontend-side by `tests/unit/test_frontend_goldens.py`; D extends it to the *emitted* section).
