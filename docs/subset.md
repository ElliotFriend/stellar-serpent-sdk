# The serpent subset

serpent compiles a restricted subset of Python to a Soroban contract.
This document is generated, in full, from the compiler's own registry
of diagnostic codes, its `tests/must_reject/` fixture suite (107 minimal counter-examples, one per rejected
construct), and its recognized-surface tables -- never hand-authored,
so it cannot say something the compiler does not actually do.

1. [What compiles](#1-what-compiles) -- the authoring surface, by area.
2. [What rejects](#2-what-rejects) -- every `SPT####` code, by band,

## 1. What compiles

### 1.1 Declarations

Every top-level class needs exactly one of @contract/@contracttype/@contracterror/@contractevent/@contractunion/@contractenum. A method's `self` must come
first, every parameter and the return both need a chain-type
annotation, and `__init__` compiles to the constructor. 25
declaration-shape rules are enforced end to end; see [SPT4xxx](#spt4xxx----contract-shape-declarations) below
for the exact list.

### 1.2 Types

A bare literal with no chain type in scope is rejected (SPT3008):
wrap the literal in a chain type, e.g. U32(5). Operators are restricted to
same-width, same-signedness operands, and `==`/`<`/`<=`/`>`/`>=` are
restricted to the types the on-chain value model can actually order.
21 type rules are enforced end to end; see [SPT3xxx](#spt3xxx----types) below for the exact
list.

### 1.3 Env API

`env.storage()`/`env.ledger()`/`env.events()` and address authorization
each lower to exactly one host function call (or, for a defaulted
storage read, a `has` then `get`-or-default pair). Every recognized
surface:

| Python | Host function(s) |
| --- | --- |
| `<Event instance>.publish(env)` | `contract_event` |
| `<bucket>.del_(key)` | `del_contract_data` |
| `<bucket>.get(key, T)` | `get_contract_data` |
| `<bucket>.get(key, T, default=d)` | `has_contract_data`, `get_contract_data` |
| `<bucket>.has(key)` | `has_contract_data` |
| `<bucket>.set(key, value)` | `put_contract_data` |
| `addr.require_auth()` | `require_auth` |
| `addr.require_auth_for_args(args)` | `require_auth_for_args` |
| `env.events().publish(topics, data)` | `contract_event` |
| `env.ledger().sequence()` | `get_ledger_sequence` |
| `env.ledger().timestamp()` | `get_ledger_timestamp` |
| `instance().extend_ttl(threshold, extend_to)` | `extend_current_contract_instance_and_code_ttl` |
| `persistent()/temporary().extend_ttl(key, threshold, extend_to)` | `extend_contract_data_ttl` |

Storage keys are drawn from one of three buckets: `instance()`,
`persistent()`, `temporary()`.

A bare `<bucket>.get(key, T)` with no `default` carries a reserved
runtime error code (`0xfffffffd`) for a missing key;
give `default=...` to get a value back instead of a trap.

#### Storage keys

A storage (or `Map`) key is not restricted to `Symbol`: any chain
value may key a bucket, including a `@contracttype` (struct) instance
(dossier D7) -- `BalanceKey(owner=...)` in `tests/fixtures/token_style.py`
is the intended shape for a keyed record.

**Note (E3):** struct storage keys are not modelled in tier 1's
ordering. The compiler's own key-ordering model (`val_cmp`, the same
one used to pre-sort a literal `Map(...)`'s keys onto the host's
linear-memory form) has no rank for structs, so it can never answer an
ordering question about one at compile time. This does not block
compiling a struct-keyed `Map` or storage entry -- the host itself
orders a struct correctly on chain -- it only means the compiler will
never claim to have PROVEN an order over struct keys the way it does
for scalars; that behavior is pinned by the differential test suite
instead, not by this compiler's static model.

Recognized, but not yet lowerable (`SPT1033`, landing in M2): `env.call()`, `env.crypto()`, `env.current_contract_address()`, `env.deployer()`, `env.logs()`, `env.prng()`, `env.try_call()`.

### 1.4 Containers

`Vec(T[, [items]])`, `Map(K, V[, [(k, v), ...]])`, and
`MyStruct(field=value, ...)` construct the three container/struct
shapes; a literal built entirely from compile-time values lays out
directly, and anything else falls back to the incremental host
build-up form. `value.field` reads a struct
field. The mutating methods below are every method these classes carry:

**`Vec` methods**

| Method | Lowers to |
| --- | --- |
| `append` | `v.append(other)` |
| `del_` | `v.del_(index)` |
| `first_index_of` | `v.first_index_of(value)` |
| `get` | `v.get(index)` |
| `insert` | `v.insert(index, value)` |
| `pop_back` | `v.pop_back()` |
| `pop_front` | `v.pop_front()` |
| `push_back` | `v.push_back(value)` |
| `push_front` | `v.push_front(value)` |
| `put` | `v.put(index, value)` |
| `slice` | `v.slice(lo, hi)` |

**`Map` methods**

| Method | Lowers to |
| --- | --- |
| `del_` | `m.del_(key)` |
| `get` | `m.get(key)` |
| `has` | `m.has(key)` |
| `key_by_pos` | `m.key_by_pos(position)` |
| `keys` | `m.keys()` |
| `set` | `m.set(key, value)` |
| `val_by_pos` | `m.val_by_pos(position)` |
| `values` | `m.values()` |

**`Bytes`/`BytesN` methods**

| Method | Lowers to |
| --- | --- |
| `slice` | `b.slice(lo, hi)` |

A container mutator (`push_back`, `set`, `del_`, ...) is only legal as
its own statement on a local this method owns outright -- the host's
container ops are functional, so `v.push_back(x)` compiles to a
rebind (`v = vec_push_back(v, x)`); anywhere else it is `SPT1034`.

### 1.5 Control flow

`if`/`while`/`for x in range(...)`/`for x in <Vec>` all compile, as do
`return` and `raise <ErrorEnum>.<Member>`. Iteration is narrower
elsewhere: iterate a Map via map.keys()/map.values(); walk Bytes with a while loop indexed by bytes[i] up to len(b); tuples cannot be iterated; range() supports only range(stop) and range(start, stop) in M1.
Every method proves it returns on every
path and never reads a local before it is definitely assigned;
5 flow rules are enforced end to end -- see [SPT1xxx](#spt1xxx----unsupported-construct) (statement/loop shape) and [SPT7xxx](#spt7xxx----flow-analysis) (return/definite-assignment/recursion) below for the exact lists.

## 2. What rejects

### SPT1xxx -- unsupported construct

#### SPT1001

**Construct:** nested FunctionDef / closures

**Intent:** nested functions and closures are not supported; contracts are a flat set of methods and module-level helpers

#### nested function definition (`constructs/closure_nested_def.py`)

```python
from serpent import Env, U32, contract


@contract
class Contract:
    def compute(self, env: Env, x: U32) -> U32:
        def helper(y: U32) -> U32:  # HERE
            return y + U32(1)

        return helper(x)
```

- **message:** nested functions and closures are not supported; contracts are a flat set of methods and module-level helpers: `FunctionDef` is not part of the serpent subset
- **help:** define the helper at module level, or as a private method on the contract class

- **note:** ValueError: a variant payload carries at most 12 values (S4's tuple arity), not 13

### SPT7xxx -- flow analysis

#### SPT7001

**Construct:** Non-Void method with a path that does not return (SS C.3 rule 3; P6/S17)

**Intent:** not every path returns a value

#### method with a path that does not return (`flow/not_every_path_returns.py`)

```python
from serpent import Bool, Env, U32, contract


@contract
class Contract:
    def compute(self, env: Env, flag: Bool, x: U32) -> U32:  # HERE
        if flag:
            return x
```

- **message:** not every path returns a value: `compute` returns U32, but control can reach the end of the body without returning
- **help:** return a value on every path, or raise an error case
- **note:** wasm validation cannot catch this -- a leaked or missing operand still validates (P6) -- so the frontend proves it instead (S17)

#### SPT7002

**Construct:** Local read before it is definitely assigned on every path (SS C.3 rule 2)

**Intent:** local may be used before it is assigned

#### local read before it is definitely assigned (`flow/local_read_before_assigned.py`)

```python
from serpent import Bool, Env, U32, contract


@contract
class Contract:
    def compute(self, env: Env, flag: Bool) -> U32:
        if flag:
            x = U32(1)
        return x  # HERE
```

- **message:** local may be used before it is assigned: `x` is not assigned on every path that reaches this read
- **help:** assign the local on every path that reaches this read -- give it a value before the branch, or assign it in both branches

#### SPT7004

**Construct:** Statement unreachable after a terminal return/raise

**Intent:** unreachable code after a return or raise

#### statement unreachable after a terminal return (`flow/unreachable_after_return.py`)

```python
from serpent import Env, U32, contract


@contract
class Contract:
    def compute(self, env: Env, x: U32) -> U32:
        return x
        return x  # HERE
```

- **message:** unreachable code after a return or raise: this statement cannot be reached
- **help:** delete the unreachable code, or move it before the return/raise

#### SPT7005

**Construct:** Call-graph cycle among module-level helpers / private methods (InternalCall) -- recursion is rejected (E8)

**Intent:** recursive and mutually-recursive calls are not supported

#### call-graph cycle among module-level helpers (`flow/call_graph_cycle.py`)

```python
from serpent import Env, U32, contract


def _even(env: Env, x: U32) -> U32:
    return _odd(env, x)


def _odd(env: Env, x: U32) -> U32:
    return _even(env, x)  # HERE


@contract
class Contract:
    def compute(self, env: Env, x: U32) -> U32:
        return _even(env, x)
```

- **message:** recursive and mutually-recursive calls are not supported: `_even` is reached again through its own call graph
- **help:** give the helper a bounded `while` loop instead of a recursive call, or inline the shared step at each call site
- **note:** _even -> _odd -> _even
